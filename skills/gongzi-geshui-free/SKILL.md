# 工资个税速算·到手和年终奖

一个人的工资：逐月个税、每月到手、年终奖怎么计税更省、个税为什么突然变多。数字全部由 `scripts/geshui.py` 按累计预扣法算，回答里贴命令和输出，每个月都有算式可以对。

## 第一条规矩：先跑脚本，再下结论

问到个税、到手、年终奖金额，**一律先在技能目录跑脚本**，不心算、不估：

```bash
python3 scripts/geshui.py quick --income <每月应发> --si <三险个人> --hf <公积金个人> --special <专项附加> [--bonus <年终奖>]
python3 scripts/geshui.py bonus --bonus <年终奖>        # 只给了年终奖金额时
python3 scripts/geshui.py zones                         # 问「年终奖怎么发最省」又没给金额时，列全部临界区间
python3 scripts/geshui.py scope labor --amount 8000      # 超出范围的所得，见「什么时候停」
```

每条命令的输出都以【回答要点】开头：**回答正文先把【回答要点】逐条抄成普通文字（不放代码块，一条不删、数字不改、算式原样保留，不许缩成只有结论）**，再按下面「回答怎么写」补结构。判卷和用户只看正文，只留在代码块里的内容等于没写。

1. 命令和**完整输出**原样放进回答末尾的「脚本原样输出」代码块；正文的数字只能抄输出里的，不能自己改，**也不自己另算脚本没给的数**（如「多发 1 元多交多少」要用就跑 zones 抄）。
2. 【回答要点】里已有的依据句（政策文件名和期限、13 薪属于全年一次性奖金且一年只能用一次、首次就业要向单位书面承诺、6 万标准员工可以不适用、个人养老金领取按 3% 计税、地方社保比例以当地为准）照抄进正文，不改写、不概括。
3. 输出开头【输入与假设】里每一条「按 0 算」「假设」都要在正文点出来，并问用户实际数；有「注意：」开头的行（如三险比应发还多），说明数不合常理，先请用户核对，不把算出来的结果当结论交付。
4. 脚本回 `[E0x]` 开头的提示：照「怎么办」改参数重跑一次；还不行就告诉用户哪个数要核对，不自己估。
5. 用户给的数是「1.5 万」「1.2w」「12k」：可以原样传（脚本会换算并在【输入与假设】写「1.2w → 12000」），正文第一句写出换算：「1.2w 即 12000 元」。
6. 用户说「社保公积金个人 X」「五险一金扣 X」是**合计数**：只写 `--si X`，不要再写 `--hf`（会重复扣）；分开给了才分开写。

同类纯提示词工具心算最常错两处：累计预扣跨 36000 等档位那个月、年终奖 36000 等临界点。这两处脚本已算死，照输出写。

## 什么时候用、什么时候不用

用（买家原话）：
- 「36100 拿到手比 36000 少，请问大家真的是这样吗」
- 「还有就是年终扣税扣多少的，按哪种缴纳方式比较划算？」
- 「哪怕你每个月都是 3 万，也是 1 月缴税少，2 月缴税多。」
- 「7 月又调整五险一金了么，工资比上个月少了近 300」
- 「一旦换了工作，下家公司不知道你之前交了多少，那就从 0 开始累积，所以到年底需要补税」
- 「新个税抵扣这个算法，谁看懂了？」

不用：劳务报酬、稿酬、经营所得（个体户）、非居民个人和外籍人员工资、经济补偿金、股权激励——见[什么时候停](#什么时候停超出范围)。

## 开工前先问：缺什么、问什么

| 缺的 | 怎么办 |
|---|---|
| 每月应发（税前）| **必须问**，没有就不算。只给到手（税后）的，说明脚本按税前算，请给税前；也可以试 2~3 个税前数跑出到手逼近 |
| 社保公积金个人扣多少 | 先按假设算一版：`--base <应发> --si-rate 10.5`（养老 8%+医疗 2%+失业 0.5%），公积金不算；正文写「按假设算，地方比例以当地为准」，并问实际扣款或缴费基数、公积金比例 |
| 专项附加扣除 | 按 0 算并提醒：子女教育、3 岁以下婴幼儿照护每人每月 2000，赡养老人独生子女 3000，房贷利息 1000，房租 800~1500，继续教育 400 |
| 入职月份（年中入职）| 问是哪个月入职；**再问今年入职前有没有在别处领过工资**——没有（如应届生）加 `--first-job`，减除费用从 1 月起算 |
| 年终奖金额和发放月 | 只问「怎么发划算」又没给金额：跑 `zones` 贴出全部临界区间，说明两种计税方式要按全年工资比，再问工资和奖金 |
| 年薪多少 | 问年薪里含不含年终奖、社保公积金扣多少；先按「年薪 ÷ 12 每月发、无年终奖」写明假设算一版，并写「如果有年终奖，要比较单独计税和并入综合所得两种方式」 |
| 上年情况 | 月薪不高（全年 ≤ 6 万左右）时问：上年 1~12 月是否都在本单位、全年是否 ≤ 6 万——是就加 `--sixty-k` |

用户问的是**他自己**的到手、个税（「帮我算我每月到手多少」）却一个数都没给：只问，不编月薪、不跑示例、不给任何到手金额。用户问的是**方法**（「年终奖怎么发最省」）：跑 `zones` 贴临界区间、讲两种计税方式怎么比，再问他的数。

能推断的就推断并写明假设（「月薪」默认税前、默认 1~12 月全年在本单位、年终奖默认 12 月发）；会改变结论的（入职月、首次就业、6 万标准、年终奖金额）先问。

## 按场景跑哪条命令

| 用户在问 | 跑这个 | 正文先写 |
|---|---|---|
| 每月到手多少 / 个税多少 | `quick --income 20000 --si 2100 --hf 1400 --special 2000` | 第 1 个月和最后一个月的到手和个税、全年合计 |
| 只知道缴费基数和比例 | `quick --income 20000 --base 20000 --si-rate 10.5 --hf-rate 7` | 同上，并写出三险、公积金各扣多少 |
| 某个月个税为什么变多 | `quick ...` 照用户的数跑到那个月之后 | 抄【个税和到手为什么变了】那几行：哪个月跨过哪个档、税率从几升到几、全年不多交 |
| 年中涨薪 / 某月发绩效 | 加 `--income-from 7=20000` / `--income-set 6=30000` | 变化那个月的个税和原因 |
| 7 月调社保基数 | 加 `--si-from 7=2300` | 抄【个税和到手为什么变了】：到手少了多少、个税变了多少，两个数分开说 |
| 年终奖单独计税还是并入 | `quick ... --bonus 30000` | 两种方式全年合计、哪个省、省多少、单独计税算式 |
| 只给了年终奖金额 | `bonus --bonus 50000` | 奖金税和到手、临界提醒；再问工资情况才能比两种方式 |
| 年终奖落进临界区间 | 同上（输出带 ⚠ 和改法一、改法二） | 多发多少、到手少多少、两个改法各让员工多拿多少 |
| 年中入职（没说是不是首次就业） | `quick ... --start 7` 和 `quick ... --start 7 --first-job` 各跑一次 | **主结果用不加 --first-job 的**（「按 7 月起算减除费用：7 月 X、8 月 Y」），再写「如果今年是首次就业（如应届生、入职前今年没领过工资）：减除费用从 1 月起算，7 月 X、8 月 Y，要向单位书面承诺」 |
| 应届生 / 今年首次就业 | 用户给了入职月就 `--start <月> --first-job`；**没给入职月就按 7 月入职假设**跑 `--start 7 --first-job`，同时问实际入职月 | 写明「按 7 月入职假设」，给出各月个税，写首次就业依据和要向单位书面承诺 |
| 年中换工作、汇算补税 | 前单位 `quick ... --end 6`、后单位 `quick ... --start 7`、全年合并 `quick ...`（不加 start/end）各跑一次 | 两边各预扣多少（都没算错）、全年合并应纳多少、补税 = 合并应纳 − 两边已预扣；原因是新单位从 0 重新累计 |
| 上年全年 ≤ 6 万的老员工 | `quick ... --sixty-k` | 哪个月开始扣、每月多少 |
| 公积金比例超 12% | `quick ... --base 30000 --hf-rate 15` | 能扣多少、超出多少不能扣、单位超缴部分并入工资 |
| 个人养老金 / 商业健康险 | 加 `--other 1000`（个人养老金每年上限 12000） | 加之前和加之后全年个税各多少（跑两次），并写领取时按 3% 计税、边际税率越高越划算 |
| 13 薪 / 年终双薪 | 当作年终奖：`quick ... --bonus <13薪金额>` | 先写「13 薪属于全年一次性奖金（年终加薪），可以选单独计税，一年只能用一次」，再写两种合计 |

参数全表和更多例子见 `references/params.md`；口径和临界点表见 `references/tax-rules.md`。

## 回答怎么写

结构固定，结论在前：

1. **结论**（1~2 行）：直接回答用户问的那个数（到手 / 个税 / 哪种更省 / 是不是算错）。
2. **要点**：【回答要点】逐条抄成正文列表。
3. **逐月表**：贴【逐月个税与到手】表（普通 Markdown 表格，不放代码块；只问一两个月的可以只贴那几行）。
4. **关键算式**：用户问到的月份，抄【逐月算式】对应行（普通文字）。
5. **要你确认的**：【回答要点】里「要你确认」那几条改写成问题，加上本题还缺的数。
6. **脚本原样输出**：命令 + 完整输出，放代码块。

写法规矩：
- 只写脚本算出来的数；用户自己给的个税数和脚本不一致时，写「按累计预扣法应为 X，差 Y」，并点出最可能的原因（没累计、跨档月份按老办法算、漏了年终奖税）。不说「公司算错了」，说「可以请单位核对这一步」。
- 个税逐月变多是累计预扣法的正常现象，要写「全年总税额不会因此多交」。
- 年终奖改法只写「省员工的税、公司总支出不变」，不写「公司也少花钱」。
- 预扣不是最终结果：涉及补税、退税的，写次年 3 月 1 日至 6 月 30 日年度汇算多退少补。

## 什么时候停（超出范围）

下面这些**不跑 quick**（quick 只算居民个人工资薪金和全年一次性奖金），**跑 `scope`**，把它的【回答要点】逐条抄成正文（第一句就是固定开头「这一类（…）不归本技能计算……以单位和主管税务机关确认为准」）；用户给了数就带上数跑，让脚本算出具体金额。补充说明读 `references/out-of-scope.md` 对应小节。

| 用户在问 | 跑这个 |
|---|---|
| 劳务报酬、讲课费、兼职费、设计费 | `scope labor --amount 8000` |
| 稿酬 | `scope royalty --amount 8000` |
| 个体户、个人独资、合伙的经营所得 | `scope business --profit 300000`（个体户加 `--getihu`；只说「赚」多少的，写明按利润假设） |
| 外籍人员、非居民个人工资 | `scope foreign --income 50000` |
| 外籍人员住房补贴、子女学费等免税 | `scope allowance` |
| 拆工资、发票抵工资等避税 | `scope avoid` |

各类要点：

- 劳务报酬、稿酬、讲课费、兼职费：按次预扣，不并进工资累计。
- 经营所得（个体户、个人独资、合伙）：五级超额累进 5%~35%，按年算。
- 外籍人员、港澳台人员、非居民个人（一年在境内不满 183 天）：按月算、不累计，有补贴免税和协定问题。
- 经济补偿金、股权激励、年金领取、退休人员。
- **避税要求**（把工资拆成劳务费、开发票抵工资、做两套工资表、找人代领）：明确说不做，说明风险；只给合法做法：年终奖选对计税方式、避开临界区间、专项附加扣除填全、个人养老金、公积金在 12% 以内足额缴。合法做法能算的照样跑脚本。
- 整张工资表、几十个人批量算、出工资条 Excel：本技能一次算一个人（可以逐人跑 quick）。用户问到时如实说：同店另有收费版可以读整张工资表、出带公式的 Excel 和工资条。用户没问不提。

**半年奖、季度奖、一年想单独计税两次**：直接判定——全年一次性奖金单独计税一个纳税年度只能用一次；半年奖、季度奖、绩效奖不属于全年一次性奖金，**不能单独计税，应并入发放当月工资按累计预扣法计算**。已经把半年奖错按单独计税申报的，**建议单位在扣缴端更正那个月的申报**（改为并入当月工资），这样 12 月的年终奖还能选单独计税；员工自己在个税 App 里不能把工资改成奖金。

**问「个税突然变多 / 到手突然变少」但没给数时**：四类原因都列出来，再要数：① 累计应纳税所得额跨过 36000、144000 等档位，税率升一档（工资不变也会发生）；② 本月收入变多：绩效、奖金、补发工资、加班费并入当月；③ 扣除变少：专项附加扣除到期没续报、社保公积金基数调整；④ 年中换单位、单位预扣方式变了。要的数：每月税前应发、社保公积金个人、专项附加、哪个月多了多少。不在没数时断定公司算错。

**输入明显不对时先停**：月份写 13 月（一年只有 12 个月：先指出没有 13 月，问是 12 月还是 13 薪，两种都给出怎么算）；社保扣款比应发还多、比例超过 30%、月薪像年薪：先指出哪里不合常理、最可能是什么写错了，请用户核对，不把算出来的结果当结论。

## 常见问题

| 现象 | 怎么办 |
|---|---|
| 脚本回 `[E01]` 参数写法不对 | 照 `python3 scripts/geshui.py -h` 改；月份变化写成 `7=18000` |
| `[E02]` 金额要写数字 | 「1.5 万」写成 15000，不带「元」「k」 |
| `[E03]` 月份不对 | 月份 1~12；年终奖发放月要在 `--start`~`--end` 之间 |
| `[E04]` 负数 / `[E05]` 超出合理范围 | 核对是不是多打了 0、把年薪当月薪、把全年专项附加当成每月 |
| `[E06]` 参数互相矛盾 | `--first-job` 和 `--sixty-k` 不能同时用；`--sixty-k` 要从 1 月算 |
| `[E09]` 脚本内部出错 | 按 `references/manual.md` 手算，回答里写明「脚本出错，以下为手算，请复核」 |
| 没有 Python | 同上手算；只要 Python 3.8+，不用装任何包 |
| 和个税 App / 工资条差几分钱 | 四舍五入口径不同，差额小于 1 元可忽略 |
| 和工资条差得多 | 先核对：社保公积金是不是同一个数、有没有漏专项附加、是否年中入职、是否发过奖金、单位是否按累计预扣 |

错误码全表见 `references/errors.md`。
